## Задание: Микросервисная архитектура для игры космичеческий бой

[Просмотр диаграммы](https://drive.google.com/file/d/1JyksrLZ_kVf2Ki4gOb4rZsiytdjKstaT/view?usp=sharing)

### Сервисы:
1. Авторизация / аутентификация пользователей - ожидает запрос пользователя и либо выдает токен с доступом к действиям, либо отклоняет.
2. Сервис игр - создает игры для действий пользователей или эмулирует прошедшую игру по заранее записанным действиям пользователей.
3. Сервис турниров - обрабатывает заявки на участие, создает игры при наступлении времени, ведет рейтинг турниров
4. Сервис уведомлений - обрабатывает запросы на уведомления и отправляет пользователю (смс, нотификация, e-mail и т.д.)

### Базы данных:
1. Пользователи
2. Игры (все игры, включая тип турнир)
3. Турниры (информация + связка с id играми)


### Узкие места:
1. Потеря авторизации пользователя во время игры. Решение: автоматическое обновление токена, если игра.
2. Эмуляция игры предполагает новый расчет для всех действий пользователя. Если есть расчет с погрешностями или со случайными числами, то результат будет не тот, который был изначально. Решение: хранить в играх не действия пользователя, а конечный результат. То есть по идее получится цепочка последовательностей перемещений и состояний.
3. С рейтингом - можно хранить в БД Игр и избавиться от БД Турниров, но выглядит, как хорошо бы иметь свой сервис.

### Компоненты, к которым чаще всего будут меняться требования
1. Компонент для окружения игры. Например: лимит игроков, характеристики игровых объектов (летает, плавает, ползает), игровое поле может быть ограниченное или стать бесконечым.
2. Сервис уведомлений - могут меняться типы уведомлений, появляться расписание, способы выводу пользователя.
